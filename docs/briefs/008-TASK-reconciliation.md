## Objective

Everything so far records what CloFin believes happened. Reconciliation is where
that belief meets a second, independent account of the same events — the
scheme's statement — and every disagreement becomes a tracked, owned, ageing
fact instead of a spreadsheet surprise. The PRD's own framing (§2): a break
found in March may have originated in January, and this increment is why that
cannot happen here.

After this task: a synthetic statement can be generated and ingested; every
line is matched by a deterministic rule that records *which* rule; every
unmatched line is a break with an age and an assignee; a break resolved by
adjustment posts a real journal entry under the existing approval machinery;
and reconciliation status is reportable per account and period.

## Scope

### In

1. **A synthetic statement format, CloFin-defined** — JSON, versioned, carrying
   the `SIM-` scheme name, a statement period, and lines with scheme reference,
   amount in minor units, currency, value date and a line type. **Deliberately
   not any real scheme's or bank's schema** (no camt, no MT940, no BAI2): a
   synthetic-data project parsing a real bank format would be fidelity theatre,
   and naming one would invite exactly the misreading the scope statements
   exist to prevent. Record the format in an ADR (next-available number, L-1).
2. **Synthetic statement generation** — from the simulated scheme's own record
   of what it did, with named perturbation classes applied on request: a
   missing line, an amount mismatch, a line CloFin never saw settle, a
   duplicate line, a shifted value date, and an unperturbed statement that
   matches completely. **The generator must not share matching logic or match
   keys with the matcher** — a statement generated by the matcher's own rules
   proves the matcher agrees with itself (L-16: agreement is only worth
   something between values produced by different things).
3. **Ingestion** — `POST`, authenticated, idempotent by canonical content
   digest (L-2/L-12: the digest covers every effect-bearing field; an exact
   replay returns the original outcome, a same-identity-different-body arrival
   gets `409`). **Receipt and disposition are separate facts (L-11)**: a
   statement whose processing is refused is still recorded as received, with a
   machine-readable disposition, and the refusal renders after the receipt
   commits.
4. **Deterministic matching in a documented order** — rules applied in a fixed
   sequence; the first match wins; every match records the rule id it matched
   under (PR-051). The rule order and each rule's definition are documented in
   `DOMAIN_MODEL.md`, and **a guard compares the documented rule list with the
   code's, both directions (L-6)** — the vocabulary-drift shape already used
   sixteen times over.
5. **Breaks** — an unmatched line (or an unmatched expected movement: the check
   runs both directions, a statement line with no ledger counterpart *and* a
   ledger expectation with no statement line) becomes a break carrying: what
   disagreed, the age (derived from timestamps, never stored), and an assignee.
   **The break lifecycle is data** in the `clofin.payments.state` shape —
   states, transitions table, terminal set derived — enforced at the service
   boundary; an illegal transition is a `409`/`422`, not a silent update.
6. **Resolution by adjustment (PR-053)** — an adjustment posts a balanced
   journal entry through the **existing posting path** (zero-sum trigger and
   all), in the same transaction as the break's resolution and its audit
   event. Above the per-currency threshold it requires approval through
   `clofin.authz.approval/evaluate`; **the actor who created the adjustment
   cannot approve it** (C-01's shape, extended to adjustments); below the
   threshold a single actor may post, and the threshold table says so.
7. **Reconciliation status per account and period (PR-054)** — a read endpoint
   summarising matched / unmatched / breaks-by-state for an account and period.
   `Should`-priority: if it threatens the increment, objecting with a proposed
   cut is legitimate.
8. **Control C-13 — reconciliation integrity** — a new `COMPLIANCE.md` §2
   entry stating what this machinery guarantees, with enforcement points named
   per claim. **Every universal quantifier names its set and boundary (L-14)**
   — write the statement from the enforcement outward, not from ambition
   inward. Regenerate the control map (`make diagrams`).
9. **Audit coverage** — every new write records exactly one event in its
   transaction (I9 pair per action, committed → one, rolled back → none). New
   actions and subject types extend `clofin.audit/actions`, the OpenAPI
   `AuditAction` enum **and the `EvidencePack` subject enum — both copies
   (the TASK-005/L-6 incident; do not repeat it)**.
10. **UAT** — next-available number against the live tree (L-1), covering the
    ingest → match → break → adjust → approve walk.

## Traps, named

- **The clearing account is the point.** The scheme's statement is the scheme's
  view; `1300-IN-TRANSIT` is CloFin's (ADR-0018). The reconciliation of that
  account — including the timed-out item that is *correctly* still in transit
  on CloFin's books and *correctly* absent from the statement — is the case
  that shows the model working. Perturbation class "line CloFin never saw
  settle" and its mirror are not edge cases; they are the product.
- **A returned item's retry is a new instruction (ADR-0019).** A statement line
  bearing the original's scheme reference must match the original, and a line
  bearing the retry's must match the retry. If your match key makes these
  ambiguous, the key is wrong.
- **`C-05` is unqualified on `main` and must still be after you merge.** If any
  write you add lacks its event, the compliance claim regresses from ✅ to
  false — not to "partial".
- **Age is derived, never stored** — a stored age is wrong the moment it is
  written (the same reasoning as balances derived from the journal).

## Notes for whoever picks this up

**Reconciliation is a reader, a matcher and a break ledger — not a corrector.**
Nothing in this increment edits a journal entry, ever (C-03): the only way a
disagreement changes the books is a new, approved, balanced adjustment entry.
If you find yourself wanting an update statement, you are holding the wrong
tool.

**Objections are expected and have a strong record**: the last two increments
filed ten between them and all ten were ruled in the Worker's favour. A
numbered objection with your reasoning beats a silent workaround, and beats a
stalled increment.
